Today's focus: the yellow box. How does RAGFlow decide which chunks are "the best"?

Meaning is a direction An embedding turns text into an arrow

Imagine the model rates every text: how much is it about regulation? security? hardware? 3 numbers = an arrow.
"PRRC signs EU assessments" → [0.9, 0.1, 0.1]
Texts about the same topic point the same way.
real models use 1024 numbers, with no names
The question becomes an arrow too, with the same model.
"Who approves changes for EU products?"
Vector similarity = how small the angle is.

Keyword score = how much of the question's (weighted) words appear in the chunk. Rare words count more. Common words like "the" are ignored.

Full-text vs vector

QuestionFull-text (keywords)Vector (meaning)
K231187 ✔ exact hit. The code appears in the register. ✘ weak. A code has no "meaning" to point at.
Who approves changes for EU products? ✘ misses. The SOP says "PRRC must sign…", not "approve". ✔ finds it. Same meaning, different words.
Typo: "Garduian ICD" ✘ no such word. ✔ usually close enough.
Each one misses what the other finds. RAGFlow runs both and mixes the scores: hybrid search.

Keyword similarity weight How to mix the two scores

score = 0.7 × keyword + 0.3 × vector
keyword partvector partquestion: "Who must sign changes for EU products?"
Users search by codes and names? Raise it. Users ask in free words? Lower it. Default: 0.7.
Vector similarity weight = 1 − keyword weight. Same knob, other side.

Similarity threshold The passing grade

Chunks below the line are dropped. They never reach the LLM.
Too high: the answer may be cut.
Too low: noise gets in.
Nothing passes? RAGFlow returns the Empty response, without calling the LLM.

PageRank Prefer one dataset over another

Dataset: Acme SOPs (official) · PageRank 10
"Triage must be done within 3 business days." rev D
score 0.48 + 10 = 10.48
Dataset: Old team wiki · PageRank 0
"Triage must be done within 5 business days." 2023 page
score 0.61 + 0 = 0.61
A dataset setting (0–100). It's added to every chunk score of that dataset, so the official answer wins. Leave it at 0 when the assistant uses one dataset.

Where vectors fail An arrow captures the topic, not the details

Both chunks are about "products + Bluetooth vulnerability", so their arrows point the same way. The word NOT barely moves an arrow. The wrong chunk wins.

A rerank model is a small AI model with one job: "how well does this chunk answer this question?" It reads both, like a person, so it notices the NOT.

So why not always rerank? Because it's slow

Vector search
Chunk arrows are computed once, at upload.
A question = 1 new arrow + simple angle math.
100,000 chunks → milliseconds.
Rerank model
Nothing can be prepared in advance: it needs the question.
Every question × every chunk = one model run.
100,000 chunks → 100,000 runs. Per question.

Like hiring: screen 1,000 CVs quickly, then interview only the best 64. In RAGFlow's score, the rerank score takes the vector's place: 0.7 × keyword + 0.3 × rerank

Top N How many chunks go into the prompt

After scoring, only the best N chunks are pasted into the prompt. Default: 8.
Small N: cheap and focused, but an answer spread over several chunks gets cut. Here, N = 1: the LLM never sees the update to 3 days.
Large N: more complete, but more tokens (cost), and more noise for the LLM.
